# Data Live Dashboard 工程说明（中文）

## 1. 项目用途

本工程是一个浏览器端实时数据仪表板，配套 Raspberry Pi Pico 2 USB CDC 测试固件。网页通过桌面浏览器的 Web Serial API 与板载 USB 虚拟串口通信，展示实时数据、记录运行数据、导出 CSV 文件、对历史 CSV 进行三张同步交互图表分析，并支持加载赛道文件、显示设备当前位置和高度/遥测实时曲线。

> **重要说明：** Pico 2 固件只发送模拟遥测值，用来检查网页功能；它不是实际电机控制或车辆控制固件。参数写入只更新 RAM，重启后会恢复默认值。

## 3. 网页模块分工

### `index.html`：界面骨架

定义四个页面：

- **遥测界面：** 显示转速、油门、功率、速度、运行统计和速度曲线；提供串口连接、记录和 CSV 导出控制。
- **数据分析：** 加载 CSV 后，用户可为三张图分别选择数值列。三图共用第一列作为时间标签，并且横轴缩放与复位同步。
- **参数设置：** 提供八个参数输入框、串口连接控制，以及读取/写入参数按钮。
- **赛道显示：** 通过导航栏路线图标进入；加载 CSV/GPX 轨迹，在上方画布绘制赛道与 GPS 位置，下方曲线可选择高度、转速、油门、功率或速度。

脚本会按 `id` 查找 HTML 控件，因此修改控件 `id` 时，必须同步检查 `app.js` 中的 `elements` 和参数映射。

### `style.css`：统一布局与视觉效果

颜色和控制面板高度通过 `:root` CSS 变量集中管理。`--controls-panel-height` 决定各页面底部控制/状态栏的统一高度。分析页使用三行网格布局；赛道页上方为较大的赛道窗口，下方为较矮的实时曲线。鼠标滚轮缩放、拖动框选和双击复位由 JavaScript 实现。

### `app.js`：前端业务控制器

负责：

1. 连接 HTML 控件和模块对象；
2. 管理串口状态显示，以及连接成功前禁用“开始记录”和“导出 CSV”；
3. 分发转速、油门、速度、功率遥测帧；
4. 以固定周期采样，计算距离、能耗和平均功率；
5. 初始化 Chart.js、处理图表同步鼠标交互；
6. 导出带默认防重文件名的 CSV，并导入历史 CSV 进行分析；
7. 解析 CSV/GPX 赛道文件，绘制 GPS 路线和设备标记，并采样高度/实时遥测曲线。

### `serial-manager.js`：串口生命周期

封装 `navigator.serial.requestPort()`、端口打开、后台读取循环、写入队列和断开清理。模块以 `statechange`、`data`、`error` 事件通知主控制器，避免业务逻辑直接持有底层 reader/writer 锁。

### `protocol.js`：通信帧协议

集中处理帧编码、参数值编码、读取参数请求、逐字节状态机解析及 ASCII 数字校验。

### `csv-utils.js`：CSV 解析

解析带引号字段、字段内逗号、双引号转义和换行；同时提供有限数字转换。CSV 数据以字符串读取，图表需要绘制数值列时再单独转换。

## 4. CSV 导出格式

导出的第一列时间格式统一为 **`MM:SS.cc`（分:秒.百分之一秒）**，即用户要求的 `00:00.00` 样式。

| 秒数 | CSV 时间字符串 |
|---:|---|
| 0 | `00:00.00` |
| 2.5 | `00:02.50` |
| 12.34 | `00:12.34` |
| 65.37 | `01:05.37` |

CSV 表头如下：

```csv
time_mm_ss_cs,cadence,resistance,power_W,speed_kmh
00:00.25,82.4,42.5,151.0,22.7
00:00.50,82.8,43.0,153.0,22.9
00:00.75,83.2,43.5,155.0,23.1
```

- `time_mm_ss_cs`：从开始记录起经过的时间，以分钟、秒和百分秒显示。由于当前采样周期为 250 ms，数据常见间隔为 `.00`、`.25`、`.50`、`.75`；格式显示两位小数不代表采样率达到 100 Hz。
- `cadence`：转速，单位 RPM。
- `resistance`：油门/阻力百分比，单位 %。
- `power_W`：功率，单位 W。
- `speed_kmh`：速度，单位 km/h。

导出的 CSV 使用 UTF-8 BOM，便于 Excel 识别编码。时间列为文本标签，数据分析页面直接把它当作 X 轴标签；其他被选中的列会转换为数值。文件默认名为 `日志_YYYYMMDD_HHMMSS_NNN.csv`，同一天导出时编号递增以降低默认命名重复的概率。

浏览器支持 `showSaveFilePicker()` 时会弹出系统文件保存窗口。该 API 在桌面版 Chrome/Edge 的安全上下文（通常为 `localhost` 或 HTTPS）中使用体验最佳。浏览器不支持时，网页会提示原因，不会静默改为直接下载。

## 5. 串口帧协议

通用帧格式：

```text
F1 | TYPE | LENGTH | PAYLOAD... | CHECKSUM | F6
```

- `F1`：帧起始标记。
- `TYPE`：一字节类型编号。
- `LENGTH`：载荷字节数，不包含帧头、校验和和结束标记。
- `PAYLOAD`：ASCII 数字文本，例如 `82.5`。
- `CHECKSUM`：载荷所有字节累加后取低 8 位。
- `F6`：帧结束标记。

| 类型 | 含义 |
|---:|---|
| `0x41` | 转速 / RPM |
| `0x44` | 油门/阻力 / % |
| `0x42` | 速度 / km/h |
| `0x4A` | 功率 / W |
| `0x51`–`0x58` | 八个参数，顺序与参数设置页一致 |
| `0x60` | 读取全部参数请求 |

读取参数请求使用专用帧 `F1 60 00 00 F6`。该协议约定是按当前网页与测试固件之间的实现整理的；连接实际硬件前，应先与真实固件协议逐项核对，尤其是长度字段、校验范围、参数类型和单位。

## 6. 本地运行网页

1. 安装桌面版 Chrome 或 Edge，并使用支持数据传输的 USB 线连接 Pico 2。
2. 在 `dashboard_refactor` 目录启动本地静态服务器：

   ```bash
   python -m http.server 8000
   ```

3. 浏览器访问 `http://localhost:8000`。
4. 点击“连接设备”，在系统串口选择窗口中选择 Pico 2 的 USB CDC 端口。
5. 确认转速、油门、功率和速度持续变化，再测试记录、导出、参数读写和 CSV 分析。

Web Serial API 需要安全上下文，直接双击 `index.html` 可能无法连接设备。Pico 2 的 USB CDC 使用 USB 传输，因此界面波特率选项只是 Web Serial API 所需的配置字段，不是 USB 物理链路的实际 UART 波特率。

## 7. 编译 Pico 2 固件

本机需要安装 Raspberry Pi Pico SDK 和 CMake/Ninja 或其他受支持的生成器，并将 `PICO_SDK_PATH` 环境变量设置为 SDK 根目录。进入 `pico2_test_firmware` 目录执行：

```bash
cmake -S . -B build -DPICO_BOARD=pico2
cmake --build build
```

生成的 UF2 通常位于 `build/pico2_dashboard_test.uf2`。烧录时按住 Pico 2 的 BOOTSEL 按钮并连接 USB，待电脑出现 `RPI-RP2` 磁盘后松开按钮，将 UF2 文件复制到磁盘；设备重启后应枚举为 USB CDC 虚拟串口。

## 8. 记录统计口径

- **采样周期：** 250 ms，也就是约 4 个采样点/秒；串口遥测包本身以更高频率到达时，界面仍以固定周期记录一组快照。
- **距离：** 对速度进行梯形积分，单位换算使用小时，输出 km。
- **能量：** 对功率进行梯形积分，单位换算使用小时，输出 Wh。界面中的 HTML id `calories` 是历史命名，实际显示的是 Wh。
- **平均功率：** 能量积分值除以有效采样时长，不采用不规则数据包计数的算术平均。
- **遥测超时：** 2 秒内未收到新遥测时，积分按速度和功率为零处理，避免旧数据继续累加。

## 9. 安全与维护提醒

1. 当前参数范围仅是前端基础校验；真实 MCU 必须再次校验合法范围和安全约束。
2. 图表缩放只改变显示范围，不会删除或篡改 CSV 原始数据。
3. 同一个 USB CDC 通道中不要混发调试文字，因为它会破坏二进制协议帧流。
4. 修改协议编号时，要同步修改 `protocol.js`、`app.js` 和 `pico2_test_firmware/main.c`。
5. 修改 CSV 表头时，要同步检查数据分析页面对首列时间标签和其他数值列的处理逻辑。
6. 当前交付完成了静态代码检查和格式化逻辑验证；仍需用户本机安装 Pico SDK 后编译，并在实体 Pico 2 上完成最终联调。


## 8. 赛道显示界面

### 界面布局

导航栏“参数设置”按钮右侧新增赛道路线图标。赛道页复用网页的同一 `SerialManager`，因此在任一页面连接或断开串口，所有页面的状态灯都会同步。页面中间分为上下两块：上方是赛道路线及设备位置窗口，下方是高度/遥测数据曲线；曲线图所占高度较小，底部保留与遥测界面同高度的串口操作区。

### 赛道文件格式

支持 CSV 和 GPX：

- CSV 首行必须有经纬度表头，例如 `latitude,longitude,elevation_m`，或 `lat,lon,height`，也支持中文“纬度”“经度”“高度”“海拔”。其他列可以同时存在。
- GPX 读取 `trkpt`、`rtept` 和 `wpt` 节点的 `lat`、`lon` 属性，并读取可选的 `ele` 高度值。
- 路线至少需要两个有效经纬度点。该界面将经纬度投影到本地平面并保留长宽比例，背景网格仅为视觉参考，不是在线地图底图。
- 完整网页工程附带 `dashboard_refactor/sample_track.csv`，可与 Pico 2 测试固件的模拟位置配合使用。

### 设备位置与高度

网页接收下列扩展数据帧来更新赛道位置和高度：

| 类型 | 字段 | 约定 |
|---|---|---|
| `0x45` | 高度 | 米，ASCII 数字 |
| `0x46` | 纬度 | 十进制度，范围 -90 至 90 |
| `0x47` | 经度 | 十进制度，范围 -180 至 180 |

帧封装格式与现有遥测一致：`F1 | type | length | ASCII payload | checksum | F6`，校验和为载荷字节之和的低 8 位。实际使用 GPS 或高度传感器时，应由设备端按此协议发送真实数据；若现有设备已定义不同类型编号，应修改 `dashboard_refactor/app.js` 的 `handleFrame()`。

赛道窗口会在收到新的经纬度后自动刷新标记。点击“刷新设备位置”可基于当前最新坐标再次绘制，并且只有串口连接成功、赛道已加载且坐标有效时才允许操作。若设备 GPS 和赛道数据不属于同一区域，状态栏会提示当前位置在赛道范围外。

### 实时曲线

赛道页曲线下拉框可选择设备高度（m）、转速（RPM）、油门（%）、功率（W）或速度（km/h）。这些遥测量与遥测界面共用同一份串口状态。连接并持续接收数据时，网页约每 250 ms 采样一次，最多保留 1200 个点用于显示；这条曲线不要求先按下“开始记录”。

### Pico 2 测试固件

`pico2_test_firmware/main.c` 已扩展为发送 `0x45`/`0x46`/`0x47` 三类模拟数据。纬度和经度围绕示例赛道中心构成椭圆，海拔随时间变化。加载示例 CSV 后，可在赛道页观察红色设备标记沿路线移动，并切换下方曲线验证高度和四项遥测。它们是模拟值，不代表真实位置或高度。
