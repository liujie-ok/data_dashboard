# Data Live Dashboard — 重构版

## 文件结构

- `index.html`：页面结构，保留遥测、数据分析、参数设置三个页面。
- `style.css`：原有样式 + 小屏响应式调整。
- `protocol.js`：串口帧编码、流式帧解析、数值校验。
- `serial-manager.js`：Web Serial 连接、读取循环、串行写入和锁释放。
- `csv-utils.js`：支持带引号字段、逗号、转义双引号和换行的 CSV 解析。
- `app.js`：UI 绑定、图表、遥测显示、骑行统计、参数读写和 CSV 导入导出。

## 启动

Web Serial API 通常需要安全上下文（HTTPS 或 localhost），并建议使用桌面版 Chrome / Edge。不要直接双击 HTML 后就假定串口功能一定可用；可在项目目录启动本地静态服务器，例如：

```bash
python -m http.server 8000
```

然后访问 `http://localhost:8000`。

## 当前沿用的串口协议假设

数据帧：`F1 | type | payload_length | ASCII payload | checksum | F6`。

- 校验和：payload 每个字节累加后取低 8 位。
- 参数值以 ASCII 数字字符串发送。
- 读取参数请求保留旧代码的特殊帧 `F1 60 00 00 F6`。
- 遥测类型沿用 `0x41` 转速、`0x44` 油门/阻力、`0x42` 速度、`0x4A` 功率；参数类型沿用 `0x51` 至 `0x58`。

这些是根据原前端代码保留的假设，必须和 MCU 固件核对。尤其需要确认：长度字段是否仅表示 payload 长度、checksum 是否只覆盖 payload、特殊读取请求是否确实要求两个 `00` 字节，以及固件是否接受 ASCII 小数。

## 统计口径

- 距离：速度 km/h 对时间小时积分，结果为 km。
- 能耗：功率 W 对时间小时积分，结果为 Wh；UI 仍沿用原 `calories` 元素 ID，但显示内容改为 Wh。
- 平均功率：按时间积分计算，不再使用不规则到包次数的算术平均。
- 若 2 秒内没有收到遥测数据，积分时按速度和功率为 0 处理，避免断流时继续累加旧值。

## 注意事项

1. 参数范围目前是保守的前端基础校验，最终范围应以设备固件和硬件安全要求为准，MCU 端必须再次校验。
2. `20 ms` 参数帧间隔只是为兼容可能处理较慢的旧固件保留，不是防止 USB 粘包的机制；正确解析应由协议边界和长度字段保证。
3. 还没有单片机固件、真实串口录包或测试设备，因此本次只完成静态检查和 JavaScript 语法检查，不能声称已经完成端到端验证。


## 数据分析图表操作

- 页面不提供外层滚动；分析区三张图始终纵向排列，并在当前窗口可用高度内自适应。
- 分析区三张图表的缩放与复位操作保持同步。
- 缩放只改变显示范围，不会删改导入的 CSV 原始数据。
